## Implemented

- The main input Schema embeds the shipped road-network contract with offline
  references. Runtime rejects invalid supplied options before solving, including
  explicit nulls; omitted fields retain their defaults.
- Accepted projects retain skeleton/version, source/official/project object
  mappings, candidate snapshots and enforced input definitions. Reopening does
  not silently drop quotas, area scopes, classifications or vehicle geometry.
- A ladder road can be locked through `ProjectService.lock_road`. Regeneration
  selects candidates satisfying the locks and retains the accepted revision on
  conflict. The same local segment ID in a different skeleton is not treated as
  the same project object. Successful regeneration updates the accepted site.
- Every evaluated ladder candidate has frozen road/stall geometry. The offline
  viewer switches between those snapshots without rerunning the solver.
- Matrix resume binds source commit, input hashes, dependencies and ceilings;
  mismatched runs are rejected. Windows timeouts terminate the owned worker
  process tree, avoiding leftover solves contaminating subsequent cells.

## Fixed matrix protocol

24 synthetic cases × family off/on × greedy/CP-SAT × promotion off/on × road
traversal off/on × 3 repeats = 1152 sequential cells. The existing 180-second
single-case ceiling, 16 skeletons, eight full evaluations and 20-second default
refinement budget remain fixed. Requested-road input budgets are unchanged.
Timeouts, invalid results and unsupported cases remain recorded; they are not
discarded or called passes. Source is pinned to a clean detached checkout and
the worker imports an independently installed wheel.

Launch/recovery command (use the same output directory only with identical
source, inputs, Python and dependencies; the runner checks this):

```powershell
$matrixRoot = 'H:/program/OpenParkCAD/output/verification/v0_5/20260912-closeout'
$matrixPython = 'E:/CacheVault/Temp/openparkcad-v05-closeout-20260912/venv/Scripts/python.exe'
& $matrixPython -I "$matrixRoot/matrix-source/tools/v0_5_n9_matrix.py" --out "$matrixRoot/matrix" --python $matrixPython
```

Do not start a second copy while the current matrix process is running. This is
a sequential host-dependent measurement; it does not establish isolated-host
latency under all loads. The main worktree can receive documentation changes
without changing the detached matrix source.

The 20/20 wide-bay journey fixture is separate from this frozen matrix. The
original dense N-T01 case remains a limitation/negative test. Completing a
